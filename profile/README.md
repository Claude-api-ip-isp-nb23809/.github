<h2>一、先确认你是不是真的需要独享</h2>
<h3>三种情况可以先用共享</h3>
<p>账号数量在五个以内、每天只在固定时段用一两个小时、彼此之间不要求绝对隔离，这三种情况共享出口完全够用，成本能压到独享的三分之一以下。共享的问题不是不能用，而是你无法控制同段其他人在做什么，所以它适合低频、可重来的账号。</p>
<h3>三种情况必须上独享</h3>
<p>一是号有历史资产，掉了重来代价很高；二是有自动化任务长期挂着，掉线会中断正在跑的会话；三是多人共用一个后台，每个人都要能独立操作而互不影响。这三类场景里，同段邻居的行为会直接变成你的成本，独享买的就是这份可控。</p>
<h3>一个反例：为了省事而独享</h3>
<p>见过不少团队第一批就开五十条独享，结果一半账号三个月没登录过。出口闲置的成本比换线成本更高。先按活跃号数量开，闲置号留在共享池里待命，这个配比比一刀切更省钱。</p>

<h2>二、出口规格的六项必查</h2>
<h3>归属与运营商</h3>
<p>要的是原生家宽，不是机房段伪装成住宅。查 ipinfo.io 的 asn 与 org，家宽会挂在本地运营商名下；再查 ipapi.is 的 is_datacenter，返回 true 的一律不要。双 ISP 的意思是同一条住宅线路上有两家运营商的路由可达，主线路抖动时能切到另一家，这个特性在长连接场景里价值明显，但需要供应商明确说明是不是真双上行，而不是两条不同机柜的线路。</p>
<h3>纯净度与历史</h3>
<p>问三个问题：这条 IP 之前有没有被用于同类平台、最近三十天有没有被投诉记录、同一 /24 里现在有多少活跃客户。前两个问题供应商未必肯答全，但第三个可以从外部抽样验证。纯净度不是零风险的同义词，它只表示这段地址近期没有明显的滥用痕迹。</p>

<h2>三、计费与交付方式的取舍</h2>
<h3>按账号、按并发还是按流量</h3>
<p>按账号算适合长期在线的号，成本可预期，缺点是闲置也照付。按并发算适合任务型使用，峰值高但平均低的时候省得多。按流量算适合调用量波动大的场景，缺点是长连接空转也会产生少量流量，月底容易超预期。三种方式没有优劣，只看你的曲线形状：平稳就按账号，尖峰就按并发，长尾就按流量。</p>
<h3>交付时要拿到什么</h3>
<p>至少要拿到四样：每条出口对应的账号或凭证、出口 IP 与归属地清单、切换或补线的方式、以及出问题时的响应时限。缺任何一样，后面都会变成扯皮。特别是响应时限，口头承诺「尽快」等于没有承诺，写进单子里才有约束力。</p>

<h2>四、上线前的验收清单</h2>
<p>验收分三步，每步都要留记录。第一步单条打通，用 curl 连续打二十次目标接口，看成功率与延迟分布；第二步并发压测，按实际峰值的 1.5 倍跑十分钟，看有没有被限速或断开；第三步挂机观察，连续 24 小时跑低频心跳，记录断连次数与恢复时间。</p>
<h3>三步的判定标准</h3>
<p>单条成功率不低于 99%，P95 延迟在可接受范围内；并发压测不出现连续失败；24 小时断连不超过两次且能自动恢复。三项都过才算验收通过，有一项不过就先换线，别急着放量。</p>
<h3>验收不过怎么写反馈</h3>
<p>把时间点、IP、请求方式、返回码、复现步骤整理成一页，发给供应商。含糊地说「不稳定」通常换来一句「我们这边正常」，带着数据的反馈才会被当真处理。</p>

<h2>常见问答</h2>
<h3>双 ISP 出口和两条普通线路有什么区别？</h3>
<p>答：双 ISP 指同一住宅接入点有两条不同运营商的上行路径，主路径抖动时可以切换到另一家而不改变出口归属。两条普通线路通常只是两台不同机柜的机器，归属地往往对不上。</p>
<h3>独享出口会不会因为只有我一个人用而显得异常？</h3>
<p>答：不会。真实家庭宽带本来就是一个人或一家人使用，独享更接近这种形态。异常与否看的是行为模式，不是使用人数。</p>
<h3>预算有限时优先保哪一项？</h3>
<p>答：优先保 ASN 归属和 is_datacenter 这两项硬指标，其他可以放宽。硬指标不过，后面再怎么优化都是白费。</p>
<h3>一条独享出口能接几台设备？</h3>
<p>答：技术上不限制，但建议同一出口下的设备数不超过三台，且不要在同一时刻发起同类请求，否则行为特征会变得不像家庭网络。</p>
